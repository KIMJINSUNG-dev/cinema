# Cinema 개발 로드맵

> 최초 작성: 2026-10-01 · 최종 수정: 2026-10-21 · 최소 완성본 목표: 2027-01-29

영화 예매 시스템 Cinema의 개발 재개 이후 일정과 범위를 정리한 문서입니다.
각 단계가 끝날 때마다 진행 상황과 일정 변경 내역을 이 문서에 반영합니다.

## 1. 범위

### 최소 완성본

이 범위가 완료되면 Cinema를 완성된 프로젝트로 봅니다.

- 상영관 · 좌석 · 좌석 등급 · 상영 일정 관리
- 예약과 좌석 동시성 처리 (DB 락)
- 좌석 등급별 가격 차등
- 예매 내역 조회 · 취소
- 이메일 인증 · 비밀번호 재발급 · 아이디 찾기
- PG 결제 (샌드박스)
- QueryDSL 기반 동적 검색과 N+1 대응
- 통합 테스트와 CI
- 사용자 화면, 관리자 화면 (기존 관리자 API 범위)

### 확장

최소 완성본 이후 우선순위에 따라 진행합니다.

- **(우선)** 관리자가 API로 상영 일정 여유 시간 변경 (운영 설정 테이블, 현재는 설정 파일 값)
- 대관 등 비공개 상영 상태(예: PRIVATE) 추가
- 결제 전 재인증, 반복 로그인 실패 알림
- Redis 기반 동시성 처리 고도화
- OTP 2단계 인증
- 회원 등급 할인, 시간대별 할증
- 신규 API가 필요한 관리자 기능 (통계 등)
- 배포와 CD
- LLM API 연동 기능

### 범위 밖

- 모니터링, 도메인 · SSL 등 운영 영역

## 2. 진행 원칙

### AI 활용 방식

이 프로젝트는 Claude(대화형)와 Claude Code(에이전트형)를 함께 사용합니다.
작업 성격에 따라 아래 두 가지 **작업 방식** 중 하나로 진행하며, 각 작업에 표기를 붙입니다.

| 표기 | 의미 | 진행 절차 | 적용 대상 |
| --- | --- | --- | --- |
| **[직접 구현]** | 코드는 개발자가 작성, AI는 가이드와 리뷰 담당 | 개념 학습 → AI의 설계 방향 · 힌트 → 직접 작성 → AI 리뷰 | 새로운 개념의 첫 작업, 보안 · 결제 · 동시성 관련 작업 |
| **[AI 초안]** | 초안은 AI가 작성, 리뷰와 최종 판단은 개발자 담당 | 리뷰 체크리스트 작성 → AI 초안 + 구현 의도 설명 → 직접 리뷰 · 수정 | 이미 만든 패턴과 같은 구조의 후속 작업 |

- 작업 시작 전에 AI가 이 문서의 표기를 근거로 작업 방식을 제안하고, 개발자가 확인한 뒤 진행합니다. 표기가 없는 작업은 방식을 먼저 정합니다.
- [AI 초안] 작업은 초안을 받기 전에 리뷰 체크리스트를 먼저 작성합니다.
- 인증 · 권한, 예외 처리, 트랜잭션, 쿼리 관련 코드는 방식과 관계없이 직접 검토합니다.
- Claude Code의 작업 규칙은 `CLAUDE.md`에, 설계 결정과 근거는 `docs/decisions.md`에 기록합니다.

### 검증

- 테스트가 있는 코드는 테스트 통과 후에만 커밋합니다.
- push 시 GitHub Actions에서 빌드와 테스트를 자동 실행합니다.
- 개발자 승인 없이 AI가 커밋하지 않습니다.

### 일정

- 평일 작업을 기준으로 하며, 주말과 공휴일은 제외합니다.
- 일정 내 공휴일: 10/5(개천절 대체공휴일), 10/9(한글날), 12/25(성탄절), 1/1(신정)
- 단계가 목표보다 1주 이상 늦어지면 마감일을 미루지 않고 범위를 조정합니다.
- 각 단계 종료 시 다음 단계의 일정과 범위를 점검합니다.

## 3. 핵심 결정

**QueryDSL은 최소 완성본에 포함하며, 예약 기능 직후에 적용합니다.**
관리자 화면의 상영 일정 검색처럼 동적 조건 검색이 실제로 필요한 지점이 생기고,
예매 내역 조회는 영화 · 상영 · 좌석을 함께 조회하므로 N+1 문제가 발생하는 지점입니다.
프론트엔드 개발 전에 조회 API를 확정해 이후 API 변경을 줄이는 목적도 있습니다.

**통합 테스트와 CI는 예약 기능보다 먼저 구축합니다.**
동시성 처리는 테스트 없이 검증하기 가장 어려운 영역이기 때문입니다.
