# [AI 초안] 리뷰 체크리스트

> 최초 작성: 2026-10-29

[AI 초안] 방식에서 Claude Code가 만든 초안을 **개발자가 리뷰할 때** 확인하는 항목입니다.
AI가 지켜야 할 규칙은 `CLAUDE.md`의 [AI 초안] 방식 항목에 있습니다.

작업을 요청할 때는 이 문서의 항목을 다시 적지 않고, **그 작업에만 해당하는 항목**(시나리오, 허용한 예외 등)만 프롬프트에 적습니다.

## 1. 공통

- [ ] **기존 코드가 바뀌지 않았는가**: GitHub Desktop의 변경 목록에 요청한 파일만 있는지 확인
- [ ] AI가 보고한 **가정 목록**을 실제 코드와 대조했는가 (메서드 이름, 상태 값 등)
- [ ] AI가 보고한 **수정 필요 사항**이 있으면 내용을 검토하고 처리 방법을 정했는가
- [ ] 참고한 기존 파일과 **같은 패턴**으로 작성됐는가. 다르게 작성한 부분은 이유가 설명됐는가
- [ ] 한 파일 안에서 같은 작업(예: 엔티티 조회)을 **서로 다른 방식으로 섞어 쓰지** 않았는가
- [ ] 인증 · 권한, 예외 처리, 트랜잭션, 쿼리 코드는 위치를 따로 보고받아 직접 검토했는가
- [ ] 작성이력 · 주석 · `@DisplayName`이 기존 코드 형식과 같고, 사람이 읽기에 이해되는가
- [ ] 초안에서 **이해되지 않는 코드**가 없는가. 있으면 커밋 전에 질문
- [ ] 전체 테스트가 통과했는가 (개수까지 확인)

## 2. 테스트 초안

테스트 작성 규칙은 `docs/decisions.md`의 D-37(통합 테스트), D-45(동시성 테스트)입니다. 리뷰에서는 아래를 확인합니다.

- [ ] 요청한 **시나리오를 빠짐없이** 작성했는가. 각 테스트가 시나리오 과정을 정확히 수행하는가
- [ ] 테스트 데이터를 **실제 서비스 메서드**로 만들었는가. 허용한 예외가 아닌데 리포지토리 · SQL로 만든 곳은 없는가
- [ ] 개발 DB가 아니라 **컨테이너 DB**(`@Import(TestcontainersConfiguration.class)`)를 쓰는가
- [ ] **성공 검증**: 예외가 없는 것만 보지 않고, 저장된 값 · 바뀐 상태까지 확인하는가
- [ ] **거부 검증**: 예외 발생만 보지 않고 **예외 종류**와 **메시지**까지 확인해, 의도한 위치 · 이유로 거부됐음을 보장하는가
- [ ] 각 테스트가 **독립적**인가 (롤백 또는 정리 코드, 실행 순서 · 다른 테스트 데이터에 의존하지 않음)
- [ ] **의도적 실패 확인**: 기대값을 하나 바꿔 실패하는 것을 확인했는가 (D-37 규칙 7)

## 3. 기능 코드 초안

- [ ] 입력 오류는 400, 상태 충돌은 409, 권한 위반은 403으로 응답하는가 (D-35)
- [ ] 변경이 있는 메서드에 `@Transactional`이, 조회만 하는 메서드에 `@Transactional(readOnly = true)`가 있는가
- [ ] 새 API 경로의 권한 규칙이 `SecurityConfig`에 추가됐는가 (기본 거부 구조, D-34)
- [ ] 본인 리소스 API는 소유권을 검증하는가 (D-14)
- [ ] 응답 DTO에 노출하면 안 되는 값(비밀번호, 내부 메시지 등)이 없는가
- [ ] 관련 설계 결정이 있으면 `docs/decisions.md` 항목과 일치하는가
